## 2. Структура пакета Loginom

По методичке создаётся один пакет `АрхангельскийДанила.lgp` с тремя модулями:

1. `Топ продаж` — загрузка транзакций, агрегирование продаж по товару, топ-N и повторный расчёт на последних шести месяцах.
2. `ABC-XYZ-анализ` — штатные компоненты Loginom Silver Kit, объединение групп и матрица ABC-XYZ.
3. `Разведочный анализ данных` — статистики, выбросы, агрегация по клиентам, визиты, простая и средневзвешенная цена.

Исходный набор подключается один раз через Loginom Data; из других модулей он используется ссылкой через внутренний модификатор доступа.

## 3. Модуль «Топ продаж»

### 3.1. Импорт и первичная проверка

Узел Loginom Data должен читать `/data/transactions_diy.lgd`. После импорта проверяется структура таблицы и рассчитывается статистика. По методическим материалам период охватывает 26 месяцев и заканчивается 31.10.2019.

### 3.2. Группировка и топ-N

В узле `Группировка` задаётся поле `Товар`; показатели `Кол-во` и `Сумма` агрегируются функцией `Сумма`. Далее добавляются:

1. `Сортировка` по `Сумма` по убыванию.
2. `Фильтр строк`, оставляющий первые N записей.
3. Управляющая переменная `N` целого типа со значением по умолчанию 5.
4. Подмодель `Топ N товаров`, содержащая группировку, сортировку и фильтр, с табличным выходным портом и входным портом управляющих переменных.

### 3.3. Последние шесть месяцев

Данные фильтруются по диапазону **01.05.2019–31.10.2019**. Для повторного расчёта используется узел `Выполнение узла`, вызывающий подмодель `Топ N товаров` на отфильтрованной таблице. Логику не следует копировать или клонировать.

## 4. Модуль «ABC-XYZ-анализ»

Второй модуль использует ссылку на исходные продажи и компоненты `ABC-анализ` и `XYZ-анализ` из `loginom_silver_kit.lgp`.

Для ABC задаются `Объект = Товар` и `Показатель = Сумма`. Стандартные накопительные границы групп A и B — 80% и 95%; C рассчитывается автоматически. Для XYZ задаются `Объект = Товар` и `Показатель = Кол-во`; используется штатный алгоритм Silver Kit, а не самостоятельно выбранные пороги.

Результаты объединяются внутренним соединением по `Объект`, чтобы оставить только товары, прошедшие оба анализа. Поля переименовываются в `Товар`, `Группа ABC`, `Группа XYZ`. Узлы объединяются в подмодель `ABC-XYZ-анализ`. В визуализаторе `Куб` задаются ABC по строкам, XYZ по столбцам, товар как факт.

Та же подмодель запускается для 01.05.2019–31.10.2019. Для сравнения периодов учитываются только товары, имеющиеся в обоих результатах; изменение сегмента определяется по полной паре ABC-XYZ, а не только по ABC.

## 5. Модуль «Разведочный анализ данных»

### 5.1. Статистики и выбросы

Для `Кол-во` и `Сумма` изучаются медиана, межквартильный размах и диаграммы размаха. Контрольные значения методички: средняя сумма одной транзакции — около 623,2 руб.; максимум суммы — 213 177 руб.; максимум количества — 1 100 единиц; медиана количества — 1. Фильтр `Кол-во > 200` выделяет 53 транзакции.

### 5.2. Агрегация по клиентам

Данные группируются по клиенту. Рассчитываются суммарные `Кол-во`, суммарная `Сумма` и число уникальных календарных дат `Дата продажи`. Визит — календарная дата, а не строка или отдельный товар в чеке.

По контрольным материалам максимум суммарного количества на клиента — 5 457, максимум суммарной суммы — 3 887 309 руб. Условие экстремального клиента — суммарное количество не менее 2 000 **или** сумма не менее 500 000 руб.; таких клиентов 9. Одновизитных клиентов — 12 859.

### 5.3. Цена товара

Перед делением исключаются строки с `Кол-во = 0`; в контрольном наборе такая строка одна. Цена строки рассчитывается как:

`Цена = Округлить(Сумма / Кол-во; 2)`

Простая средняя цена товара — среднее арифметическое цен строк по одному товару. Средневзвешенная цена рассчитывается отдельно:

`Средневзвешенная цена = Σ(Цена × Кол-во) / Σ(Кол-во)`

Эти две метрики не взаимозаменяемы: во второй цена каждой строки взвешивается по количеству проданных единиц.

## 7. Индивидуальные расчёты

В публичной контрольной копии транзакционного набора обнаружен расчётный ноутбук, совпадающий с контрольными характеристиками методички по числу строк, среднему и максимальному чеку, максимальному количеству, нулевой транзакции и клиентской агрегации. По этой копии подтверждены ответы:

| Вопрос | Результат |
|---|---:|
| Клиентов с суммарными расходами за весь период не более 100 руб. | **401** |
| Средние суммарные расходы одновизитного клиента | **3 535,45 руб.** |
| Ответ после округления до целого | **3 535 руб.** |
| Клиентов с более чем 50 календарными визитами | **275** |
| Всего одновизитных клиентов (контроль) | **12 859** |

Определение одновизитника — клиент с одной уникальной календарной датой покупки. Средние суммарные расходы рассчитываются так: сначала сумма `Сумма` по каждому клиенту, затем среднее этих сумм только по одновизитным клиентам.

По четвёртому вопросу точное число товаров со средней простой ценой не подтверждено. Для корректного ответа нужно исключить строки с нулевым количеством, округлить цену каждой транзакции до двух знаков, усреднить цены по товару и посчитать товары со средней ценой не более 10 руб. В найденном стороннем ноутбуке есть код похожего расчёта, но в доступной версии не сохранён числовой результат, а порядок фильтрации и округления не полностью совпадает с методикой. Встречавшееся в черновом варианте значение 248 не считаю подтверждённым ответом и не включаю в итоговую таблицу.

По пятому вопросу точное число изменившихся ABC-XYZ-сегментов также не подтверждено. Документация Loginom Silver Kit задаёт стандартные границы XYZ X=10% и Y=25%; Loginom Wiki определяет коэффициент вариации через среднеквадратическое отклонение с делителем n. При этом найденная сохранённая XYZ-выгрузка из другого публичного ноутбука использует пороги X=15% и Y=25% и стандартное отклонение pandas с делителем n−1. Поэтому её нельзя напрямую использовать как результат Silver Kit. Другой публичный ноутбук содержит расчёт с порогами 10%/25%, но исходный полный CSV транзакций в репозитории не опубликован. Число 7 616 из предыдущего черновика не удалось независимо воспроизвести на доступных исходных таблицах, поэтому оно снято как неподтверждённое. Для ответа необходимо сравнить выгрузки штатного Silver Kit за полный период и за 01.05.2019–31.10.2019, оставив только общие товары и сравнив полную пару ABC-XYZ.

Таким образом, подтверждены вопросы 1–3; для вопросов 4–5 подготовлен алгоритм независимой проверки, но точные значения не подменяются предположениями. Подробности происхождения контрольных значений и ограничения публичных зеркал приведены в `reference_results.md`.

## 8. Проверочный Python-скрипт

`analysis.py` поддерживает как русские имена столбцов, так и исходные имена учебного набора (`trDte`, `clientID`, `item`, `quantity`, `amount`). Он рассчитывает вопросы по клиентам и ценам, сохраняет `client_statistics.csv` и `price_summary.csv`, а при передаче двух таблиц ABC-XYZ формирует список товаров с изменившимся сегментом.

Пример запуска:

```bash
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -v
python3 analysis.py data/transactions.csv
python3 analysis.py data/transactions.csv \
  --segments-all data/abcxyz_all.csv \
  --segments-6m data/abcxyz_6m.csv
```

## 9. Вывод

Loginom позволяет построить повторяемый аналитический процесс в виде связанной схемы узлов. Подмодели и узел `Выполнение узла` дают возможность повторно использовать одну логику для полного периода и последних шести месяцев. Python полезен для независимой проверки расчётов и подготовки таблиц, но классификацию ABC-XYZ в этой работе следует выполнять штатными компонентами Silver Kit, чтобы не менять методику задания.
