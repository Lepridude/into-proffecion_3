## Вопрос 4: средняя простая цена

Точный результат не подтверждён доступными файлами. Для строгого ответа нужен полный набор транзакций за весь период. Расчёт должен выполняться в следующем порядке:

1. Посчитать записи с `quantity = 0` и исключить их до деления.
2. Рассчитать `price = round(amount / quantity, 2)` для каждой оставшейся транзакции.
3. Сгруппировать строки по `item` и вычислить простое среднее `price`.
4. Посчитать количество товаров, для которых среднее значение не превышает 10 руб.

В публичном ноутбуке `Practice_2.ipynb` есть код похожего фильтра, но доступная копия не содержит сохранённого числового результата и не полностью совпадает с порядком обработки из методички. Значение **248**, которое встречалось в черновой версии отчёта, нельзя подтвердить доступными исходными результатами; оно не выдаётся за ответ.

## Вопрос 5: изменение ABC-XYZ-сегмента

Точное количество не подтверждено. Для корректного расчёта нужны два результата штатного компонента Loginom Silver Kit: полный период и 01.05.2019–31.10.2019. Сравнивать нужно только товары, присутствующие в обеих таблицах, и полную пару `(ABC, XYZ)`.

Почему нельзя перенести найденные сторонние значения напрямую:

- Официальная документация Loginom Silver Kit указывает границы XYZ по умолчанию X=10%, Y=25%, но не публикует подробностей обработки пропусков для отдельных наблюдений: [документация компонента XYZ](https://github.com/loginom/loginom-silver-kit/blob/master/docs/xyz-analysis.md).
- Loginom Wiki задаёт коэффициент вариации как стандартное отклонение с делителем `n` и границы X 0–10%, Y 10–25%, Z выше 25%: [формула XYZ](https://wiki.loginom.ru/articles/xyz-analysis.html).
- Сохранённая XYZ-выгрузка из публичного ноутбука `rudenman/Machine-learning-loginom` была построена с порогами X=15%, Y=25% и стандартным отклонением pandas (`ddof=1`). Это отличается от стандартной конфигурации Silver Kit.
- Другой ноутбук `Practice_1_4.ipynb` показывает код с порогами X=10%, Y=25%, но исходный полный CSV транзакций в этом репозитории отсутствует.
- В этом же ноутбуке показан результат из 7 543 строк. Использовать его как число изменившихся сегментов нельзя: сравнение выполняется левым соединением по товарам, а вызовы `dropna()` не сохраняют результат обратно в таблицу. Поэтому в выборку могут попасть товары, отсутствующие в одном из периодов; кроме того, это не запуск штатного Silver Kit.
- Найдена публичная копия бинарного `transactions_diy.lgd` в стороннем учебном репозитории [Kratosyan7/siibd-mirea](https://github.com/Kratosyan7/siibd-mirea/tree/main/%D0%A0%D0%A2%204). Однако коннектор GitHub возвращает для этого бинарного файла только метаданные, не содержимое; получить и проверить сам набор для расчётов не удалось. Поэтому он не использовался как источник числовых результатов.

В черновике фигурировало значение **7 616**, однако повторить его по доступным и методически совместимым исходным данным не удалось. Это значение снято и не используется как результат. Число **3 444** в одном из сторонних ноутбуков относится только к изменившимся ABC-группам, а не к полной паре ABC-XYZ.

### Предварительное сравнение ABC-XYZ

Для полнопериодной выгрузки сохранённый `xyz_analysis.csv` содержит уже рассчитанные `mean`, `std` и `cv`. Код исходного ноутбука использует `pandas.GroupBy.std()`, то есть выборочное стандартное отклонение (`ddof=1`), а границы XYZ в нём по умолчанию X=15%, Y=25%. Для предварительной сверки группы были переназначены по официальным границам Silver Kit X=10%, Y=25%; для последних шести месяцев XYZ рассчитан тем же выборочным способом. ABC-группы за последние шесть месяцев пересчитаны по границам 80%/95%.

Получено:
- товаров, присутствующих в обеих периодных матрицах: **20 463**;
- товаров с изменившейся полной парой ABC-XYZ: **7 345**.

Это **не окончательный ответ** на вопрос 5. Документация Loginom Wiki задаёт коэффициент вариации через стандартное отклонение с делителем (n), то есть генеральное стандартное отклонение, тогда как сохранённая полнопериодная публичная таблица содержит значения, рассчитанные через выборочное стандартное отклонение. В выгрузке нет количества наблюдений по каждому товару, поэтому преобразовать полнопериодный CV к формуле Loginom нельзя. Для последних шести месяцев расчёт генерального стандартного отклонения даёт 7 417 изменившихся сегментов вместо 7 345. Следовательно, различие методик влияет на ответ, и число 7 345 остаётся только контрольной оценкой.
